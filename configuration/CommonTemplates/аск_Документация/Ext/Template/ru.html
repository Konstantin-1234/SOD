1. Общие сведения о расширении

Назначение

Расширение «СОД для Документооборота 3.0» (внутреннее имя: СОД_ДО) предназначено для интеграции системы обработки документации (СОД) с типовой конфигурацией 1С:Документооборот 3.0. Расширение реализует массовую загрузку документов из файловой структуры проектных каталогов на диске в базу 1С:Документооборота с автоматическим распознаванием структуры папок, привязкой к проектам, контрагентам и финансовым шифрам.

Авторы и история изменений

В коде модулей зафиксированы следующие разработчики:

  • Кузнецов А.А. — основная логика расширения: реквизит «Проект», переопределение HTML-обзора документа, интерфейс загрузки, проверка принадлежности к группе «СОД» (комментарии от 25.09.2026)
  • Шерер — логика работы с финансовыми шифрами: проверка заполнения, формирование представления, управление ТЧ на форме

Подсистемы

Расширение содержит одну подсистему — ЗагрузкаДанныхПодсистема, которая объединяет все объекты, относящиеся к загрузке документов из файловой системы.

3. Подсистема «Загрузка данных»

Это центральная функциональная подсистема расширения. Она обеспечивает:

  • Настройку правил загрузки через справочники-конфигураторы
  • Массовый обход файловой структуры проектных каталогов
  • Создание документов в 1С:Документообороте на основе найденных файлов
  • Сохранение отчётов о результатах загрузки

3.1. Справочник «АСК: Разделитель загрузки»

аск_сод_РазделительЗагрузки

Неиерархический справочник. Служит для разделения правил загрузки по различным проектам или источникам данных. Каждый разделитель определяет независимый набор настроек структуры каталогов и правил загрузки.

Используется в:
— реквизите РазделительЗагрузки справочника аск_сод_СтруктураКаталогаЗагрузки
— реквизите РазделительЗагрузки обработки ЗагрузитьДокументыСОД
— реквизите РазделительЗагрузки справочника аск_сод_ОтчетыЗагрузкиДанных

3.2. Справочник «АСК: Структура каталога загрузки»

Логика работы (из Module.bsl формы списка):

Форма списка предоставляет возможность «Выполнить загрузку структуры каталога в базу». Пользователь указывает:

  • Путь к каталогу — корневой путь на диске
  • Разделитель — к какому разделителю привязать структуру

При выполнении команды происходит асинхронный рекурсивный обход всех вложенных папок (функции ОбойтиСледующуюПапку, ОбходПапкиЗавершён, ОбработатьОчередьПапок). Для каждой папки создаётся элемент справочника с заполнением:

  • Наименование = имя папки
  • РазделительЗагрузки = выбранный разделитель
  • ПолныйПутьККаталогу = путь родителя + имя папки
  • СпособЗагрузкиИзКаталога = СмотретьДалее (если есть подпапки) или СоздатьДокументИЗагрузитьФайлы (если подпапок нет)
  • ПредставленияКаталога — добавляется строка с именем папки

Алгоритм загрузки (из Module.bsl обработки):

  1. Проверка заполнения — все обязательные реквизиты должны быть заполнены: КаталогПроекта, КаталогНачалаЗагрузки (должен начинаться с КаталогПроекта), РазделительЗагрузки, Организация, Проект, Контрагент
  2. СтартЗагрузкиНаСервере() — серверная инициализация
  3. Подсчёт файлов — рекурсивный поиск всех файлов СОД в точке старта, заполнение ТЧ ФайлыВсего
  4. Обход папок — ОбходПапокНаКлиенте() формирует массив структур с описанием каждой папки: имя, путь, список файлов, список файлов с группами, родительский путь
  5. Асинхронная загрузка — через НачатьЗагрузкуФайлов(...) запускается последовательная обработка каждой папки с созданием документов и загрузкой файлов

Сохранение настроек:

Обработка автоматически сохраняет и восстанавливает настройки пользователя (выбранные Проект, Организацию, Контрагента, Разделитель, пути) в ХранилищеНастроекДанныхФорм с ключом "ЗагрузитьДокументыСОД" / "ПараметрыЗагрузки".

Фильтрация файлов СОД:

Функция ЭтоФайлСОД(Элемент) определяет, относится ли файл к загружаемым. Конкретная логика фильтрации — в коде (не полностью раскрыта в найденных фрагментах).

3.6. Справочник «АСК: Финансовые шифры»

аск_сод_ФинансовыеШифры

Иерархический справочник (HierarchyFoldersAndItems). Содержит перечень финансовых шифров (аналитических кодов), которые могут быть назначены документам предприятия.

Особенности:

  • Длина кода — 10 символов
  • Автонумерация — false (ручной ввод кода)
  • Представление по умолчанию — AsCode (в виде кода)

Используется в ТЧ аск_сод_ФинансовыеШифры справочника ДокументыПредприятия.

  • ПередЗаписью (аск_сод_ПередЗаписью):
    — Проверяет, использует ли вид документа дополнительный реквизит «ФинансовыйШифр» (ищется в ПВХ ДополнительныеРеквизитыИСведения по имени)
    — Если используется и ТЧ аск_сод_ФинансовыеШифры пуста — отказ записи с сообщением «Пустой Финансовый шифр!»
    — Формирует строку представления: коды всех выбранных финансовых шифров через «; »
    — Синхронизирует с доп. реквизитами: обновляет или создаёт строку в ТЧ ДополнительныеРеквизиты со свойством «ФинансовыйШифр»
  • При пометке удаления или обмене — проверка не выполняется
  • Если вид документа не использует финансовый шифр — ТЧ аск_сод_ФинансовыеШифры очищается

Работа на уровне формы (Module.bsl):

  • аск_сод_ПриСозданииНаСервереПосле — проверяет, использует ли ВидДокумента финансовый шифр; если да — вызывает ВключитьТЧФинанансовыеШифрыНаФорму, иначе — ВЫключитьТЧФинанансовыеШифрыНаФорму
  • ВключитьТЧФинансовыеШифрыНаФорму — программно создаёт таблицу формы с колонками «Финансовый шифр» и «Наименование», перемещает группу перед «ГруппаРеквизиты»
  • ВыключитьТЧФинансовыеШифрыНаФорму — удаляет таблицу с формы
  • аск_сод_ФинШифрНачалоВыбора — открывает форму выбора справочника аск_сод_ФинансовыеШифры в режиме множественного выбора
  • аск_сод_ФинШифрОбработкаВыбора — обрабатывает множественный выбор: первое значение — в текущую строку, остальные — в новые; проверяет на дубли
  • аск_сод_ПослеЗаписиПосле — после записи перечитывает форму для обновления представления доп. реквизита

5.7. Ознакомительные задачи при запросе переноса срока

Добавлено: 2026 • Разработчик: Кузнецов / Шерер

Назначение

При изменении объекта, участвующего в процессе с запросом переноса срока, обработчик &После("ПриЗаписи") автоматически создаёт ознакомительные задачи для ключевых ролей проекта — ДУП (Директор управления проектом) и РП (Руководитель проекта). Задачи создаются однократно — при первой записи объекта; повторные записи не плодят дубликаты.

Роли

АббревиатураРольСмысл в процессе
ДУП Директор управления проектом Стратегический контроль. Должен быть в курсе любых переносов сроков по проекту.
РП Руководитель проекта Оперативное управление. Непосредственно ведёт проект и отвечает за соблюдение сроков.

Состав каждой роли определяется через цепочку:
РолиИсполнителей (эталон) → ПолныеРоли (привязка к проекту) → ИсполнителиРолей (сотрудники). Поиск эталонной роли — по GUID через функцию НайтиРольПоГуид (метод ПолучитьСсылку + Новый УникальныйИдентификатор).

Таблица решений — кому создаётся задача

№Текущий пользовательАвтор (инициатор) Задача для ДУПЗадача для РППояснение
1 ДУПне важно —— ДУП сам действует → он уже в курсе
2 РПНЕ ДУП ✔— РП информирует ДУП о переносе
3 РПДУП —— Автор — ДУП → он уже в курсе
4 третье лицоДУП —— Автор — ДУП → он в курсе
5 третье лицоРП ✔— Автор — РП, но ДУП надо информировать
6 третье лицони ДУП, ни РП ✔✔ Никто из ключевых ролей не в курсе → информируем обоих

Суть логики: ДУП — «верхний» уровень, он должен знать всегда. Если ДУП уже является действующим лицом (текущий пользователь или автор) — дополнительные задачи не нужны. Если действует РП или третье лицо — ДУП информируется. РП информируется только когда никто из ключевых ролей не участвовал (строка 6).

Защита от повторов

Реквизит объекта аск_ЗапросПереносаСрока — Булево, используется как флаг. После первого создания задачи устанавливается в Истина. 

Если не ЭтотОбъект.аск_ЗапросПереносаСрока тогда
    // ... создание задач ...
    ЭтотОбъект.аск_ЗапросПереносаСрока = Истина;
КонецЕсли;

При последующих записях флаг уже взведён → задачи повторно не создаются.

Примечания

  • GUID ролей (ДУП: 9409b47a-f136-901b-11f1-6fc56ebd51ab, РП: 9409b47a-f136-901b-11f1-7b54796604ab) зашиты в коде. При переносе между базами требуется актуализация.
  • Полные роли ищутся по проекту. Для каждого проекта должна быть заведена своя полная роль ДУП и РП (Владелец = эталонная роль, ОсновнойОбъектАдресации = Проект).
  • Если роль не найдена или у роли нет исполнителей — задача для этой роли не создаётся, ошибки не возникает.
  • Всё выполняется синхронно в рамках серверного вызова ПриЗаписи.

10. Правила оформления кода

Из файла Template.txt в составе расширения:

1. Запрещено использование вывернутой логики

Избегать конструкций, где условие отрицания усложняет чтение.

2. Запрещены короткие или лишённые смысла имена переменных

Допустимо использование стандартных имён (i, j), если зона видимости — в пределах 20 строк. Запрещено, если в одной зоне используется 3 и более подобных переменных.

3. Переносы строк в условиях «Если»

При использовании составных условий с ИЛИ — переносить на новую строку:

Если НЕ ЗначениеЗаполнено(ЭтаФорма.Разделитель)
 ИЛИ НЕ ЗначениеЗаполнено(ЭтаФорма.Разделитель)
Тогда

11. Руководство пользователя

Типовая структура каталога загрузки

Из ru.html — пример ожидаемой структуры каталогов на диске:

Исходные данные
└── Градостроительная документация
    └── ППТ и ПМТ (проект планировки территории, проект межевания территории)
        └── ПАГ ППТ и ПМТ от 23.05.2025

Общий порядок работы

  1. Настройка: Создать РазделительЗагрузки в справочнике АСК: Разделитель загрузки
  2. Загрузка структуры: В форме списка АСК: Структура каталога загрузки указать путь к корневому каталогу и Разделитель, выполнить команду «Выполнить загрузку структуры каталога в базу»
  3. Настройка правил: Для каждой загруженной папки указать ВидДокумента и СпособЗагрузкиИзКаталога
  4. Загрузка документов: Открыть обработку Загрузить документы СОД, заполнить все обязательные поля, нажать «Загрузить документы»
  5. Просмотр результатов: После загрузки формируется отчёт в справочнике АСК_СОД: Отчеты загрузки данных. Можно повторить загрузку с теми же параметрами

Заполнение финансовых шифров

  1. Создать элементы в справочнике АСК: Финанансовые шифры с указанием Кода и Наименования
  2. В форме элемента ДокументыПредприятия выбрать ВидДокумента, для которого настроен доп. реквизит «ФинанансовыйШифр»
  3. В появившейся табличной части выбрать один или несколько финансовых шифров (множественный выбор через «Подбор»)
  4. При записи документа будет выполнна проверка заполнения и сформировано представление

Работа с проектами в мероприятиях

  1. При создании пункта программы мероприятия — заполнить Проект
  2. При заполнении протокола — Проект автоматически переносится из программы в пункты протокола
  3. В пунктах протокола мероприятий — Проект обязателен к заполнению
